    「自分の環境では動く」は本番で通用しない

    利用者は、それが自分の機械で動くことを気にしていない。自分の機械で動くことを気にしている。

    利用者は予測できない

    開発者はしばしば、利用者がどう操作するかを予期できると思い込む罠に落ちる。利用者像が不完全なこともあれば、実際より分かっているつもりのこともある。

    どれだけテストを書き、どれだけのシナリオを模しても、現実の使われ方の予測不可能性は再現できない。利用者こそが最終のテストである。

    Dan は大学を出て最初の仕事で二次サポートをしていた。ある利用者から、計算機の「ドリンクホルダー」が壊れたという電話を受けた。計算機にドリンクホルダーはありません、と答えた。利用者が指していたのは CD-ROM ドライブだった。 どれだけテストしても、CD-ROM ドライブをドリンクホルダーと取り違える利用者には備えられない。

    予測不可能性の源は多い。現実のデータ、規模と同時実行、環境の多様性（OS、資源、安全設定、ブラウザ、網の遅延）、版の差による漂流、そして予期せぬ用途。

    何が環境間で変わるか

    本番の課題を読み、自分が作った機能だと気づく。再現しようとするが、できない。「再現不能」は、こういうときに課題を閉じるために使われる言葉である。 だがそれは利用者の問題を解かない。

    • 環境の差: 16GB の MacBook Pro で開発し、本番は別のメモリ制約を持つ Linux。手元は MySQL 8.0、本番は PostgreSQL 14
    • 設定管理: 手元では自分の機械のデータベースに繋ぎ、すべてをログに出し、偽のカード番号を使う試験 API を叩く。本番では安全なクラウドのデータベースに切り替わり、ログは誤りだけに絞られ、実際に課金される決済事業者に繋がる
    • 同時実行と負荷: カート機能を数回クリックして確かめた。だが商戦期には数千人が同時に同じボタンを押す。30%で巡航していたメモリが95%に跳ね上がる
    • データの多様性: 手元には自分で作った整った数百件。本番には何年分もの数百万件があり、現実の顧客データは乱雑で予測できない。レガシーシステムが違う形で保存した値が、検証ロジックを壊す
    • 外部依存: 決済が遅い、メール配信が流量制限に当たる、認証事業者が落ちる。味方の一人が不調なら、よくできたチームでも試合を落とす
    • 安全上の制約: 手元はどこからの HTTP も受けるが、本番は防火壁の奥にある。HTTPS と有効な証明書が要り、CORS が同じ要求を弾く

    溝を埋める

    コンテナ化で環境を揃える。環境の同等性──本番を忠実に映すステージングを保つ。CI/CD で本番に近い条件で定期的に試される状態にする。そして可観測性で、利用者に影響する前に問題を捕まえる。

    未知への備えとしては、カナリアリリースと A/B テストがある。現実の利用者によるテストの力を借りながら、危険を最小化する。

    設定はコードだが、コードと違う

    「設定はコードである」と言われるが、コードと違い設定は環境ごとに変わる。明るい陽射し向けに最適化した写真の設定が暗所で破綻するように、それぞれの環境に合わせた設定が要る。

    // これをやってはいけない
public class DbConnection {
    private final String url = "jdbc:postgresql://localhost:5432/fose";
    private final String username = "admin";
    private final String password = "secret";
}

    接続先、認証情報、ログ設定、外部サービスの端点、キャッシュ設定。環境ごとに設定できる形にする。 設定管理は配置工程に組み込むべきもので、後付けではない。

    効く条件

    • 「再現不能」で課題を閉じようとしたとき。差がどこから来るかを列挙する枠組みになる
    • 本番で初めて問題が出たとき。六つの差のどれかにたいてい当たる
    • 新しい環境を立てるとき。設定を外に出す判断は、最初にしか安く入らない

    効かない条件

    ここから先は本書が書いていない領域で、読み手として当て込んだ限界である。

    • 本番の規模を再現できない場合。環境の同等性は構成の話であって、負荷の話ではない
    • 外部依存を模せない場合。相手が落ちたときの挙動は、相手を落とせなければ試せない
    • コンテナ化が万能に見える場合。揃うのは実行環境であって、データも負荷も利用者も揃わない
