    学習の4段階：過去10年（2016→2026）の変化

    全体の傾向

    情報を入手し、生成する手間は大きく下がった。いま時間を取られるのは「何を問うか」と「それが正しいか」を判断するところ。

    問いから始めて作り、確かめ、残して次の問いへ進むループ型の学び方は、2016 にもあった（プロジェクトベース学習、仮説思考、ブログに書きながら学ぶ習慣）。10年で変わったのは考え方ではなく、ループを1周するコストである。問いの言語化、探索、要約、試作、成果物の生成が安くなり、4段階は直線ではなく何周も回しやすくなった。

    一次経験・違和感 → 問い → 仮説 → 調べる → 学ぶ → 作る → 確かめる → 判断する → 残す・共有する → 次の問い

    2016 の手段は消えていない。立志と発表では新しい手段が加わり、調査・学習・成果物の作り方では生成AI（以下 AI）を介する手段へ比重が移った。

    AIが教材を読む側（入力）と発表物を作る側（出力）の両方に入り、段階の境目も薄れた。たとえば NotebookLM などで縮約した教材を読んで理解し（調査・学習）、同じ資料から生成したスライドを発表の叩き台にする（共有）。

    安く回ることの副作用もある。

    • 問いの均質化: AIとの壁打ちから出る問いは平均的になりやすい
    • わかったつもり: AIが詰まりを先に解き、試行錯誤の経験が減る
    • 知識の断片化: 必要な箇所だけ読むと、自分が何を知らないかに気づけない
    • 生成物へのアンカリング: AIが作った叩き台の構成や論点に引っ張られる
    • 供給過剰: 文章やコードを作るだけでは埋もれる

    1. 立志（目的意識・問題発見・課題設定・仮説）

    2016 2026
    目的意識のきっかけ 読書、身近な人、仕事、メディア、ネットサーフィン 左記に加え、パーソナライズされた推薦、AIとの対話
    課題設定 自分や周囲の人と時間をかけて言葉にした AIとの壁打ちで数分で形になる
    仮説 調べてから立てる 最初に立てて、その場で暫定的に確かめる
    試行 予備調査や試作の初期コストが高い 比較案や試作品をすぐ作れる
    • 変化: 問いを作るのが安くなった。それらしい問いは誰でも作れるが、どれも似た問いになりやすい
    • いま効くこと: 自分の経験や現場の違和感（一次経験）を起点にする。動機が推薦から来たのか、自分の経験から来たのかを自覚する
    • いま効くこと: 問いを立てたら、仮説と「何が確かめられれば答えとするか」まで一組で書く（仮説思考とTDD（テスト駆動開発））

    2. 調査（情報の取捨・教材選び）

    2016 2026
    主な経路 検索、書籍、専門家ブログ、Qiita / Stack Overflow AIへの質問、AI検索（出典つき要約）。従来の経路も残る
    教材を選ぶ手がかり Amazonレビュー、専門家ブログ、目次やサンプルを読んだ感触 AIの評価や推薦、AI要約を読んだ感触
    教材の読み方 定番の書籍や講座を通読する 問いに必要な章だけを拾う。AIが説明の順序や言い方をその人向けに組み替える
    足りないもの 良い情報にたどり着く手段 情報が正確か確かめる手段（AI生成の文章があふれている）
    • 変化: 「探す」から「確かめる」へ。必要な部分だけ読むので、自分が何を知らないかに気づきにくくなった
    • 変化: 教材を選ぶ手がかりが、出どころの違う複数の信号から、AI という単一の経路に集まった。要約は文体や密度を落とすので、要約の感触が測るのは教材の質より要約の質かもしれない
    • いま効くこと: 情報源を証拠の強さで並べる。目安は AI回答 < 解説記事 < 公式文書 < 論文・仕様 < 自分の実験（ただし自分の実験は、自分の条件での確認にとどまる）。AIは根拠ではなく、一次資料や実験にたどり着くための探索に使う
    • いま効くこと: 何を学ぶかの全体像はAIに任せない。未知の分野や積み上げ型の分野（数学、CS基礎、形式手法）では、標準的なカリキュラムや通読で地図を得てから問いに入る（メンタルモデルは増分的に作る）

    3. 学習（記憶・反復・理解・応用）

    2016 2026
    記憶・反復 Anki、手書きノート、写経、演習問題 覚えなくても引けばよい、という前提が広がった
    理解 本や講義をノートを取りながら読み込む AIが縮約した教材（要約、比較表、スライド）を読み、AIとの対話で詰める
    応用 手を動かして詰まり、自分で抜け出す AIが詰まりを先に解いてしまう
    • 変化: 原資料と理解の間に、AIが生成する中間表現が入った。理解までは速くなった一方、「AIと話して納得した」と「自分で作れる」の差が見えにくくなった
    • 変化: 失われやすいのは知識そのものより、詰まって仮説を立て、試して直す経験
    • いま効くこと: 覚えるものを選ぶ。頭に知識がなければAIの誤答を見抜けず、何を調べるべきかもわからない（学習は習慣として設計する）
      • 外部化してよい: API名、たまにしか使わない構文、単発の事実、すぐ引ける手順
      • 内部化する: 概念と原理、制約と不変条件、因果関係、典型的な失敗パターン、評価基準（Rust なら個々の API より ownership / borrowing / lifetime の関係）
    • いま効くこと: 縮約は入口として使い、判断に効く箇所は原資料に戻って読む
    • いま効くこと: 適度に詰まる余地を意図的に残す
      • 先に自分で仮説を立ててからAIを見る
      • AIには答えでなくヒントだけを出させる
      • 解決したらAIを閉じて再実装し、日を置いてゼロから再現する
    • いま効くこと: 理解の確認は「納得したか」ではなく、自分で説明・予測・再現・修正できるかで測る

    4. 共有（発表・アーカイブ・接続）

    2016 2026
    発表 ブログ、SNS、勉強会、LT 左記に加え、短い動画、ニュースレター
    成果物の作り方 手元のノートからスライドやPDFを起こす AIが生成したスライドやHTMLを叩き台にする
    共有するもの 成果物（記事、スライド、PDF） 成果物に加え、知識を抽出・変換する手順
    アーカイブ Google Drive、GitHub、ブログ、Evernote（人が読む前提） PKB、公開ノート（人とAIの両方が読む前提）。ナレッジベースから CI と SSG で公開サイトを自動生成する（仕組みは 2016 にもあったが、構築の手間が下がった）
    接続 フォロワーやコミュニティ経由 検索に加え、AI の回答を経由して届く。ただし出典として読まれず、内容だけ使われることも多い。発信は供給過剰
    • 変化: 発信は簡単になり、ありふれた出力は埋もれる。PKB は未来の自分へのメモから、未来のAIに渡す文脈へと役割が広がった
    • 変化: 成果物が再生成できるなら、共有する価値は生成の手順の側に移る。知識源 → 変換パイプライン → 公開物という構造そのものが共有物になる
    • いま効くこと: 手順を共有するなら、プロンプトだけでなく、入力資料、問い、モデルとツール、検証方法、どの出力をなぜ採用・棄却したかも残す。同じプロンプトでも出力が変わりうるうえ、モデルは更新・提供終了されるため、プロンプトだけでは再現できない
    • いま効くこと: 生成する前に、自分の論点と判断軸を書いておく。叩き台に引っ張られないための錨になる
    • いま効くこと: 固有の経験、判断の理由、失敗を記録する。コードはAIが再生成できても、そのとき何を問題とみなし、どの制約のもとでなぜその設計を選んだかは再生成できない（決定は ADR に残しフィットネス関数で守る）
    • いま効くこと: ノートどうしをつなぐだけでなく、人とつながる場も持つ。AI経由では届いたかどうかも見えにくく、反応も返ってこないので、反応をくれる相手が直接いるほうがループは回る

    アウトプットを意識した学習への示唆

    アウトプット志向を「作りながら学ぶ」ではなく、「問い・仮説・判断とその理由を、再利用・再検証できる形で残しながら学ぶ」と捉える。

    1. 学習の単位を「本を一冊」から「問いを一つ」に変える（何を学ばないかを決める）
      • 例: 「Rust の型では保証しにくく、Lean なら保証できる実用的な性質は何か」
      • 成果は読んだページ数ではなく、立てた問い、検証した問い、残した判断、つないだ知識の数で測る。途中でやめても、検証済みの問いは残る
      • 未知の分野では、最初に概観を得る段階を例外として残す
    2. 1周を冒頭のループで回す。要は「判断する」と「残す」
    3. AIには速さを任せ、自分は判断に集中する: 問いの選択、確認、結論は自分で持つ（AI は道具であり、あなたは責任の引受人である）
    4. 完成品より判断の記録を残す: なぜその問いを選んだか、なぜ A でなく B を選んだか、何が予想と違ったか、どの証拠で考えを変えたか、AIの出力をどこで採用・棄却したか。未来の自分にとってもAIにとっても、一番使える材料になる

      • 1つの問いを、たとえば次の形で残す

        question.md        問いと仮説
sources.md         根拠とその強さ
experiment/        試したもの
decision.md        判断とその理由
workflow.md        入力・モデル・手順・検証方法
open-questions.md  未解決の点
