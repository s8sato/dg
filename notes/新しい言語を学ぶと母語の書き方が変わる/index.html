    新しい言語を学ぶと母語の書き方が変わる

    新しい言語を学ぶ価値は、その言語を使うことにはない。日常的に使わなくても、コードの書き方そのものが変わることにある。

    鍵は没入

    外国語を思えばいい。数ヶ月、ときに数年、人は新しい言語を母語に翻訳しながら使う。やがてその言語で考え、夢を見るようになる。時間がかかる。プログラミング言語も変わらない。文法規則がはるかに厳しく、キーワードがはるかに少ないだけだ。

    本気でフランス語を学ぶならパリに移り住むのが速い。プログラミング言語も同じで、職場や自宅で自分を悩ませてきた問題を、その言語で解くのがよい。コミュニティを追い、ポッドキャストを聴き、カンファレンスの動画を見る。さらに良いのは、地域の勉強会や関連イベントに出ることだ。

    道具としての言語

    開発者は最初の言語に強く愛着を持つ。ここは注意がいる。言語は道具にすぎない。 釘を打つならドライバーよりハンマーが良いように、問題によって適する言語は違う。組込みの多くが C で書かれているのは、可搬性と信頼性が高く、特定のプラットフォーム向けに深く最適化できるからだ。

    だから、選ぶなら職場で使うものと違うものを選ぶ。経験ある Java 開発者なら、C# のような C 系の言語を越えて、Ruby のような動的言語や Haskell のような関数型言語へ目を向ける。自分の近所の外にある言語をざっと眺めるだけでも、プログラミングへの取り組み方は根本から変わる。いつもの言語をより深く理解することになるかもしれないし、違う書き方をするようになるかもしれない。

    学ぶのは回を追うごとに楽になる。知っている言語が増えるほど、比較の対象が増えるからだ。最初の言語ではゼロから始めた。三つ目、四つ目、五つ目では、ある慣用表現が別の言語のそれと同じだと気づき、ある構造がどこから借りられたかが見える。

    数学ではなく言語である

    計算機科学の学科が世界の大学にできる前、プログラミングはしばしば数学科に間借りしていた。今でも数学の試験で学生を選抜する大学がある。

    だが研究が示すのは逆で、新しい言語をどれだけ速く習得できるかは、数学の能力より言語の能力のほうがよく予測する。数学の重い領域はあるが、プログラミングという営み自体はそうではない。

    プログラミングは何よりもまず伝達の活動であり、しかもコーダーとコンパイラの間の活動ではない。計算機は（構文さえ合っていれば）どんなコードも理解するが、それは人間が意図を追えることを意味しない。優れた書き手は、種類を問わず、常に読み手を念頭に置いている（コードは未来の他人に宛てた手紙である）。

    効く条件

    • キャリア中期以降。日々使う言語とフレームワークを深く掘ったあとに、横へ広げる投資が効く
    • 設計の引き出しが尽きたと感じるとき。別パラダイムの言語は、そのまま設計語彙の追加になる
    • 言語論争に巻き込まれたとき。道具として見る視点が、議論を要件の議論に戻す

    効かない条件

    ここから先は本書が書いていない領域で、読み手として当て込んだ限界である。

    • キャリア初期。広げる前に、まず一つで深さを作るほうが効く
    • 近い言語を選んだ場合。C 系から C 系へ移っても、得られるのは語彙であって視点ではない
    • 学習が「触れた」で終わる場合。チュートリアルを流すだけでは書き方は変わらない。自分の問題を一つ解くまでが最低線
