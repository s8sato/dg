    道具への投資は複利で効く

    多くの職業では、道具に責任を持つのは自分である。プロの厨房に共用の包丁立てはない。 料理人は自分の包丁を持ち込む。整備士は自分の工具箱を、自分の基準で整えて持つ。

    道具は自分に合わせる

    会社がライセンスの費用を持つとしても、道具立ての責任は自分にある。自分のものにすることを恐れない。

    隅から隅まで、すべての難解なコマンドを知る必要はない。だが日々使うものは手の甲のように知っているべきだ。

    目的は流れの状態（flow）に留まることにある。数分ごとに手を止めてコマンドを調べたり、ショートカットで済むのにトラックパッドへ手を伸ばしたりすれば、集中は途切れる。

    車に乗れば座席とハンドルとミラーを自分に合わせる。工場出荷時のままでは快適でも安全でもない。自分の光剣を組み立てるようなものだ。 フォント、テーマ、OS の設定、小さな補助アプリ。同僚のメニューバーに見慣れないものがあれば訊く。尋ねるだけで月に数時間を節約しうる。

    物理的な環境も含まれる。椅子と画面の高さ、そしてキーボード。会社が一括購入したものが自分に合っているとは限らない。 反復性ストレス障害の痛みを待つ必要はない。

    ただし時間の沼になりうることには注意がいる。本当は仕事をすべきときにフォントとテーマをいじっていた、ということになりかねない。実験には時間箱を切る。行き過ぎた個人化は、他人とペアを組むことをほぼ不可能にもする。

    コマンドラインは力の増幅器である

    最初は威圧的に見えるが、CLI はすぐに超能力になる。多くの日常作業が数打鍵で片付く。週に数分、新しいコマンドを試す時間を取る。

    パイプは、単一目的の単純な道具をつなげて複雑な出力を得させる。Git リポジトリの URL が欲しければ cat .git/config | grep url | cut -f2 -d= で済む。

    よく使うものには別名（alias）を作る。ただし自分の設定がない機械では効かないので賢く使う。履歴は最も過小評価されている側面で、逆順検索を覚えるだけで同じコマンドを二度打つことはほぼなくなる。

    0 か 1 か n か

    他人のためにコードを書いて一日を過ごしているのだから、自分のために書くことを恐れない。数行が結果的に何時間も節約する。

    計算機科学には三つの数しかない。ゼロ回やること、一度だけやること、そして n 回。 一度より多くやるなら、数え切れないほどやることになると思ったほうがいい。二度以上やることは自動化を検討する。

    ただし自動化の追求も危険な沼になりうる。コードを書くほうが作業そのものより長くかかることがある。 本当に一度きりなら、自動化は時間の使い方として賢くない。数回やってから、それでも時間箱を切って取り組む。

    覚えたことを外に置く

    技術は猛烈な速さで変わり、情報に溺れることになる。だから個人の知識管理の戦略を持つのがよい。複雑である必要も専用の道具が要るわけでもないが、後で使う情報を貯める場所は要る。

    答えを知っていたはずなのに、それがどこにあったか思い出せないことほど苛立たしいものはない。

    書き留める。同じ問題にまた出くわす。同僚も出くわす。次回には覚えていない。脳から外部記憶へ降ろす。 形式は問わない。紙片を挟んだクリップでも機能する。ただし電子的なもののほうが検索しやすく、同僚と共有しやすい。

    学びは同僚から借りる

    コツの最良の供給源は同僚である。生産性の実践について尋ねる習慣を持つ。 知らないことを恥じない。

    逆に、同僚が難しいやり方をしていたら簡単な道を示す。定着させるために三、四回繰り返してから次へ進む。 それは自分の知識を深めるだけでなく、馴染んだ環境を手元に増やすことにもなる。

    効く条件

    • 同じ操作の繰り返しに気づいたとき。二度目が自動化を検討する合図
    • 新しい職場に入ったとき。同僚の道具立てを訊くのに最も自然なタイミング
    • 手首や首に違和感が出たとき。道具への投資は健康への投資でもある

    効かない条件

    ここから先は本書が書いていない領域で、読み手として当て込んだ限界である。

    • 個人化が強すぎる場合。ペアやモブでの作業、他人の機械での作業が成立しなくなる
    • 共有環境や制限された端末で働く場合。別名も設定も持ち込めない
    • 自動化の対象が不安定な場合。仕様がすぐ変わるものを自動化すると、保守対象が増えるだけになる
