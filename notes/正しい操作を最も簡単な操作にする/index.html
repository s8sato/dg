    正しい操作を最も簡単な操作にする

    発見容易性（discoverability）はアプリケーションを学ぶ鍵である。機能が誰も予期しない場所に隠れていれば、学ぶのに時間がかかる。 十分にうまく隠せば、利用者はその機能が存在しないものと見なす。

    隠された録音ボタン

    われわれのうちの一人が毎日のように苦しんだ会議ソフトがある。音声を録音する手順はこうだった。会議番号を設定したうえで「音声をテスト」を押し、さらに「テスト後も会議音声に接続したままにする」に忘れずチェックを入れる。初めて使う人はたいてい、常用者の助けかマニュアルなしには辿り着けなかった。

    これはひどすぎて記憶には残る。何か「変な」ことをしないと動かない、と。だが数ヶ月録音しなければ、その手順を覚えているだろうか。発見容易性は記憶容易性に寄与する。迷ったら、より自明なほうを取る。

    そもそもなぜ音声を「テスト」する必要があるのか。音量メーターを最初のダイアログに置けば、あの難物の二枚目は丸ごと不要になる。

    可能な限り、利用者が誤った操作をできないようにする。フォームで正しい入力欄の型を選ぶだけで、無数の誤りが起こらなくなる。ヒント、入力マスク、書式の例を使って、正しい選択を自明にする。

    隠してよい場合もある

    すべての機能が発見可能である必要はない。機能が多すぎれば、すべてを中央には置けない。

    iPhone のピンチによる拡大を考えてみる。インタフェースを見ても、つまむと何かが起きるとは分からない。だが、つまむ＝拡大だと教えるのには二秒しかかからない。 学びやすく、記憶に残り、一度発見すれば自然に感じられる。あまりに自然なので、いまや対応していないインタフェースのほうが利用者のメンタルモデルを壊す。

    ただしこれは特殊な例だ。Apple は拡大を初期の広告の中心に据え、解説動画も用意し、そもそもピンチなしでも使えるようにしていた。鍵となる機能を隠す前に、その相互作用の利益がすぐ明らかであることを確かめる。

    逆に、発見しやすいが記憶に残らないものもある。ショートカットは熟練者の効率に不可欠だが、頻度の低い組み合わせは覚えられない。メニュー階層に併記すれば、メニューを使ううちに自然と覚える。

    エラーメッセージは回復の設計である

    利用者は完璧ではなく、間違える。誤りへの適切な応答は、使いやすさ全体を決定づける要因になることが多い。

    まず誤りが起きないようにする。それでも幸福な経路を外れたとき、意味のあるメッセージで迎える。「インタフェースが登録されていません」ではなく。良いエラーメッセージは、何が起きたのかを利用者に理解させ、代案を示す。

    そして回復させる。郵便番号を打ち間違えたからといってハードディスクを初期化してはならない。取り消しや復元の支援は、利用者が探索できるための鍵だ。戻れないなら、人は試さない。

    良い例はこうなる。接続に問題が起きたとき、暗号めいた文字列ではなく、インターネット接続の問題だと明示し、自動で再接続を試みつつ「今すぐ試す」という選択肢も置く。既定では利用者の代わりに再試行し、望むなら行動できる。

    破壊的操作にだけ摩擦を足す

    簡単にするという原則には例外が一つある。破壊的な操作だ。データの編集を難しくしたい場面はまずないが、アカウントの削除のように取り消せない決定なら、手順を一つか三つ足すのがむしろ正しい。

    GitHub のリポジトリ削除がよくできている。破壊的な設定はページ最下部にあり（近接の応用）、スクロールさせることで誤クリックを防ぐ。「Danger Zone」という見出しが危険を明示し、ボタンの色が目を引く（対比の応用。デザイン4原則は素人にも効く）。

    「このリポジトリを削除」を押しても、実際には削除されない。取り消せないと述べる警告が出て、さらにリポジトリ名を正確に打ち込まないと最後のボタンが有効にならない。

    やりすぎに見えるかもしれないが、代替はもっと悪い。ボタンのラベルが単なる「削除」ではなく、押すことで何をするのかを完全に書き下している点にも注意したい。

    効く条件

    • フォームや設定画面を設計するとき。入力欄の型とマスクだけで誤りの大半は消える
    • 「マニュアルに書いてあります」と言いたくなったとき。それは発見容易性の敗北宣言である
    • 取り消せない操作を実装するとき。摩擦・明示的なラベル・確認の三段構え

    効かない条件

    ここから先は本書が書いていない領域で、読み手として当て込んだ限界である。

    • 熟練者が一日中使う画面。摩擦は正しさではなく苛立ちになる。破壊的操作の保護も、頻度が上がれば無視され始める
    • 確認ダイアログを濫用した場合。人は訓練されて自動的にクリックするようになり、保護は機能しなくなる
    • 発見容易性と情報密度が競合する場合。すべてを見えるところに置けば、結局どれも見えない
